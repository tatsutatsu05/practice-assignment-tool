# Practice Assignment Tool

Googleフォームで集めたサークル活動の参加希望を読み込み、練習参加者の振り分けとイベント参加者の集計を行うPythonツールです。

練習の定員を超えた場合は、定員超過となった全日程をまとめて計算し、月内の練習参加回数がなるべく公平になるように参加者を選出します。

結果には、Googleフォームに入力された本名とLINE名の両方を表示します。

## 開発背景

サークルでは毎月、Googleフォームを使って練習やイベントへの参加希望を募集しています。

これまでは、フォームの回答を確認しながら、以下の作業を人の手で行っていました。

- 日程ごとの応募者整理
- 会場ごとの定員確認
- 月内の参加回数を考慮した参加者の調整
- イベントごとの参加者集計
- 本名とLINE名を確認しながら参加者一覧を作成
- 振り分け結果のCSV作成

この作業を効率化し、参加者の選出基準を明確にするため、Pythonを用いて自動化ツールを開発しました。

## 主な機能

- Googleフォーム回答CSVの読み込み
- 本名とLINE名の対応付け
- 日程ごとの練習応募者整理
- 会場ごとの定員判定
- 定員超過となった全日程を対象とする一括最適化
- 月内の練習参加回数を考慮した公平な参加者選出
- 同程度に公平な候補に対するランダムな優先順位付け
- 特定の応募者を事前に参加確定する手動確定機能
- 入力データと手動確定内容のエラーチェック
- 同じ人による同一日程・同一イベントへの重複登録防止
- イベントごとの参加希望者集計
- 本名とLINE名を含む練習結果のCSV出力
- 本名とLINE名を含むイベント結果のCSV出力

## 練習参加者の振り分け

### 会場ごとの定員

各練習には、幹部1人が引率として参加します。

そのため、一般応募者に使用できる定員を以下のように設定しています。

| 会場 | 全体定員 | 幹部 | 一般応募者の定員 |
|---|---:|---:|---:|
| 成城 | 10人 | 1人 | 9人 |
| 高島平 | 10人 | 1人 | 9人 |
| 学芸大学 | 18人 | 1人 | 17人 |

幹部の割り当てはこのツールでは行わず、一般応募者のみを振り分けます。

### 定員以内の日程

応募者数が一般応募者の定員以内であれば、応募者全員を参加者として確定します。

この参加も、その人の月内の練習参加回数に含まれます。

### 定員を超えた日程

定員を超えた日程については、1日ずつ順番に抽選するのではなく、定員超過となった全日程をまとめて計算します。

以下の優先順位で、全体として公平になるように参加者を決定します。

1. 手動確定者を必ず参加させる
2. 定員以内の日程の参加者を確定する
3. 定員超過となった全日程を同時に評価する
4. 練習参加回数が少ない人を優先する
5. 参加回数が同程度になる組み合わせを優先する
6. 公平性が同じ候補の間ではランダムな優先順位を使用する

例えば、次のような応募状況があり、各日程の定員が1人だとします。

| 日程 | 応募者 |
|---|---|
| 8/3 | A、B |
| 8/10 | A、C |
| 8/17 | A、C |

日程を1つずつ処理すると、Aが2回、Bが0回、Cが1回になる可能性があります。

本ツールでは全日程をまとめて計算するため、条件が許せば次のように割り当てます。

```text
A：1回
B：1回
C：1回
```

ただし、応募可能な日程数、手動確定、会場の定員などの制約によっては、全員の参加回数を完全に同じにできない場合があります。

その場合も、与えられた条件の範囲内で、参加回数の偏りが小さくなるように割り当てます。

### 最適化方法

定員超過となった全日程の参加枠を、最小費用最大流法を用いて一括で割り当てます。

同じ人に2回目、3回目の参加枠を割り当てるほど費用が大きくなるように設定することで、参加回数が少ない人への割り当てを優先します。

これにより、日程の処理順に結果が左右されにくい振り分けを実現しています。

### 新歓生・在サー生の区分

Googleフォームでは、新歓生・在サー生の区分を取得しています。

ただし、現在の練習参加者の振り分けには使用していません。

### グループ分け

会場内での2人組や3人組の作成は行いません。

このツールでは、各日程の参加者一覧を決定するところまでを担当します。

## 本名とLINE名

Googleフォームから、以下の2つの名前を読み込みます。

- 本名
- LINE名

ターミナル上では、以下のように同時に表示します。

```text
田中太郎（LINE名：たなか）
```

CSVファイルでは、本名とLINE名を別々の列として出力します。

LINE名が空欄の場合は、処理を中止してエラーを表示します。

同じ本名で異なるLINE名が登録されている場合も、人物を正しく識別できないためエラーを表示します。

## 手動確定機能

特定の応募者を、指定した練習日程の参加者として事前に確定できます。

手動確定された参加も、その応募者の月内の練習参加回数に含まれます。

手動確定者を登録した後の残り枠について、全体最適化による参加者選出を行います。

手動確定者は、`data/manual_assignments.csv`に記入します。

```csv
schedule,name
8/3(月)成城 17:40~,田中太郎
8/10(月)学芸大学 10:00~,佐藤花子
```

`name`には、Googleフォームに入力された本名を記入します。

日程と本名は、Googleフォーム回答CSVに記録されている文字と完全に一致させる必要があります。

手動確定する人は、その日程に実際に応募している必要があります。

手動確定者を指定しない場合も、以下の見出しだけを残してください。

```csv
schedule,name
```

## 入力内容の検証

入力ファイルに以下のような問題がある場合は、処理を中止してエラーを表示します。

- Googleフォーム回答CSVに必要な列がない
- GoogleフォームでLINE名が空欄になっている
- 同じ本名で異なるLINE名が登録されている
- フォーム回答に存在しない日程を手動確定ファイルで指定した
- その日程に応募していない人を手動確定した
- 同じ日程で同じ人を重複して手動確定した
- 手動確定者だけで定員を超えた
- 手動確定ファイルで日程または名前の一方だけが空欄になっている
- 手動確定ファイルの見出しが正しくない
- 日程名から会場を判定できない
- 振り分け後の人数が会場の定員を超えている
- 応募者と振り分け結果が一致していない
- 手動確定者が振り分け結果に含まれていない

## 重複回答の処理

同じ人がGoogleフォームを複数回送信し、同じ練習日程やイベントを複数回選択していた場合でも、同じ人を同一日程・同一イベントに重複して登録しません。

ただし、現在は本名を人物の識別に使用しています。

同じ本名の別人がいる場合は、正しく区別できない可能性があります。

## イベント参加者の集計

Googleフォームの「参加したいイベント」への回答を読み込み、イベントごとの参加者数と参加者一覧を集計します。

イベントについては、以下のルールで処理します。

- 応募者は全員参加
- 定員なし
- 抽選なし
- 手動確定なし
- イベント参加は練習参加回数に含めない
- 本名とLINE名を同時に出力する

練習の振り分けとイベントの集計は、同じGoogleフォーム回答CSVから別々に処理します。

```powershell
git clone <このリポジトリのURL>
cd practice-assignment-tool
```

### 2. dataフォルダを作る

```powershell
mkdir data
```

### 3. サンプルデータをコピーする

```powershell

Copy-Item .\sample_data\manual_assignments_sample.csv .\data\manual_assignments.csv
```

### 4. プログラムを実行する

```powershell

```

```text

```

## 実際のGoogleフォーム回答を使用する方法

Googleフォームの回答をGoogleスプレッドシートで開き、CSV形式でダウンロードします。

ダウンロードしたファイルの名前を、以下に変更します。

```text
responses.csv
```

そのファイルを、次の場所に保存します。

```text
data/responses.csv
```

すでに同名のファイルが存在する場合は、実際のGoogleフォーム回答で上書きします。

公開用の`sample_data/responses_sample.csv`は、実際のデータで上書きしないでください。

## Googleフォーム回答CSV

現在のプログラムでは、以下の列名を使用します。

```text
お名前
LINE名（正確にお願いします）
参加したい練習日程(一部10時からの枠があります)
参加したいイベント
```

列名が異なる場合は、`main.py`内の設定を実際のフォームに合わせて変更する必要があります。

### 複数選択回答

1人が複数の日程やイベントを選択している場合、GoogleフォームのCSVではカンマ区切りで保存されます。

例：

```text
8/3(月)成城 17:40~, 8/10(月)学芸大学 10:00~
```

プログラムはこの文字列をカンマで分割し、それぞれの日程の応募者として登録します。

## 練習結果のターミナル表示

ターミナルでは、本名、LINE名、選出方法を以下のように表示します。

```text
練習の振り分け結果
====================

8/3(月)成城 17:40~
定員：9人
応募者数：10人

【参加者】
・田中太郎（LINE名：たなか）（手動確定）
・佐藤花子（LINE名：さとう）（全体最適化）

【落選者】
・高橋美咲（LINE名：みさき）
```

最終的な参加回数と、全応募者間における参加回数の最大差も表示します。

```text
最終的な練習参加回数
====================
田中太郎（LINE名：たなか）：2回
佐藤花子（LINE名：さとう）：1回
高橋美咲（LINE名：みさき）：1回

参加回数の最大差：1回
```

応募可能日程数や手動確定などの条件によっては、最大差が2回以上になる場合もあります。

## 練習結果のCSV出力

練習の振り分け結果は、以下のファイルに保存されます。

```text
output/assignment_results.csv
```

出力する項目は以下のとおりです。

| 項目 | 内容 |
|---|---|
| 日程 | 応募した練習日程 |
| 結果 | 参加または落選 |
| 本名 | Googleフォームに入力された本名 |
| LINE名 | Googleフォームに入力されたLINE名 |
| 選出方法 | 定員内確定、手動確定、全体最適化、または全体最適化で未選出 |
| 最終練習参加回数 | 月内で参加が確定した練習回数 |

出力例：

```csv
日程,結果,本名,LINE名,選出方法,最終練習参加回数
8/3(月)成城 17:40~,参加,田中太郎,たなか,手動確定,2
8/3(月)成城 17:40~,参加,佐藤花子,さとう,全体最適化,1
8/3(月)成城 17:40~,落選,高橋美咲,みさき,全体最適化で未選出,1
```

そのため、以下のファイルとフォルダは`.gitignore`によってGitHubの公開対象から除外しています。

```text
data/responses.csv

```

GitHubには、架空の本名とLINE名で作成した`sample_data`のみを公開します。

実際の参加者データを、`sample_data`にコピーしないよう注意してください。

実際のデータを使用した後は、次のコマンドで個人情報を含むファイルがGitの管理対象になっていないことを確認できます。

```powershell

```

`data`や`output`が表示されなければ、`.gitignore`が正しく機能しています。

## 抽選結果の再現性

現在は、同程度に公平な候補が複数ある場合の優先順位を、乱数によって決めています。

開発中に同じ結果を再現できるよう、乱数のシードを固定しています。

```python
RANDOM_SEED = 42
```

同じ入力データと同じ設定を使用すると、原則として同じ結果になります。

毎回異なる結果にしたい場合は、乱数シードの扱いを変更する必要があります。

乱数は公平性の判定よりも優先されません。

まず参加回数が公平になる割り当てを計算し、その公平性が同じ候補の間でのみ乱数を使用します。

## 現在の制限

### 同姓同名

現在のプログラムでは、本名を応募者の識別に使用しています。

そのため、同姓同名の応募者がいる場合は、正しく区別できません。

同じ本名で異なるLINE名が登録された場合は、誤った振り分けを防ぐためエラーを表示します。

### 応募可能日程の違い

応募した日程が1日だけの人と、多数の日程に応募した人では、割り当て可能な条件が異なります。

そのため、すべての参加者の参加回数を必ず同じにできるわけではありません。

### 手動確定による影響

手動確定者は必ず参加するため、手動確定の内容によっては参加回数の差が大きくなる場合があります。

### 過去月の参加回数

現在の公平性判定で使用するのは、読み込んだ1か月分のフォーム回答内の参加回数だけです。

過去の月の参加回数は考慮していません。
