# Practice Assignment Tool

Googleフォームで集めたサークル活動の参加希望を読み込み、練習参加者の振り分けとイベント参加者の集計を行うPythonツールです。

練習日程が定員を超えた場合は、月内の練習参加回数がなるべく均等になるように参加者を選出します。

結果には、Googleフォームに入力された本名とLINE名の両方を表示します。

## 開発背景

サークルでは、毎月Googleフォームを使って練習やイベントへの参加希望を募集しています。

これまでは、フォームの回答を確認しながら、以下の作業を人の手で行っていました。

- 日程ごとの応募者整理
- 会場ごとの定員確認
- 参加回数を考慮した当選者の調整
- イベントごとの参加者集計
- 本名とLINE名を確認しながら参加者一覧を作成
- 振り分け結果のCSV作成

この作業を効率化し、振り分け基準を明確にするため、Pythonを用いて自動化ツールを開発しました。

## 主な機能

- Googleフォーム回答CSVの読み込み
- 本名とLINE名の対応付け
- 日程ごとの練習応募者整理
- 会場ごとの定員判定
- 練習参加回数を考慮した参加者選出
- 同条件の応募者に対するランダム抽選
- 特定の応募者を事前に確定する手動確定機能
- 手動確定内容のエラーチェック
- イベントごとの参加希望者集計
- 本名とLINE名を含む練習結果のCSV出力
- 本名とLINE名を含むイベント結果のCSV出力

## 練習参加者の振り分け

### 会場ごとの定員

各練習には、幹部1人が引率として参加します。

そのため、一般応募者に使用できる定員を以下のように設定しています。

| 会場 | 全体定員 | 幹部 | 一般応募者の定員 |
|---|---:|---:|---:|
| 成城 | 10人 | 1人 | 9人 |
| 高島平 | 10人 | 1人 | 9人 |
| 学芸大学 | 18人 | 1人 | 17人 |

幹部の割り当てはこのツールでは行わず、一般応募者のみを振り分けます。

### 定員以内の場合

応募者数が一般応募者の定員以内であれば、応募者全員を参加者として確定します。

### 定員を超えた場合

定員を超えた日程では、処理時点での練習参加回数が少ない応募者を優先します。

練習参加回数が同じ応募者については、ランダムに順番を決定します。

参加回数の上限は設定せず、月内の練習参加回数がなるべく均等になることを目指します。

現在の実装は、参加回数を考慮しながら日程を順番に処理する方式です。

そのため、すべての日程を同時に計算した数学的な最適解を保証するものではありません。

### 新歓生・在サー生の区分

Googleフォームでは、新歓生・在サー生の区分を取得しています。

ただし、現在の練習参加者の振り分けには使用していません。

### グループ分け

会場内での2人組や3人組の作成は行いません。

このツールでは、各日程の参加者一覧を決定するところまでを担当します。

## 本名とLINE名

Googleフォームから、以下の2つの名前を読み込みます。

- 本名
- LINE名

ターミナル上では、以下のように同時に表示します。

```text
田中太郎（LINE名：たなか）
```

CSVファイルでは、本名とLINE名を別々の列として出力します。

LINE名が空欄の場合は、処理を中止してエラーを表示します。

同じ本名で異なるLINE名が登録されている場合も、人物を正しく識別できないためエラーを表示します。

## 手動確定機能

特定の応募者を、指定した練習日程の参加者として事前に確定できます。

手動確定された参加も、その応募者の月内の練習参加回数に含まれます。

手動確定者を入れた後の残り枠については、通常の公平性を考慮した選出を行います。

手動確定者は、`data/manual_assignments.csv`に記入します。

```csv
schedule,name
8/3(月)成城 17:40~,田中太郎
8/10(月)学芸大学 10:00~,佐藤花子
```

`name`には、Googleフォームに入力された本名を記入します。

手動確定する人は、その日程に実際に応募している必要があります。

手動確定者を指定しない場合も、以下の見出しだけを残してください。

```csv
schedule,name
```

## 入力内容の検証

入力ファイルに以下のような問題がある場合は、処理を中止してエラーを表示します。

- GoogleフォームでLINE名が空欄になっている
- 同じ本名で異なるLINE名が登録されている
- フォーム回答に存在しない日程を手動確定ファイルで指定した
- その日程に応募していない人を手動確定した
- 同じ日程で同じ人を重複して手動確定した
- 手動確定者だけで定員を超えた
- 手動確定ファイルで日程または名前の一方だけが空欄になっている
- 日程名から会場を判定できない

## イベント参加者の集計

Googleフォームの「参加したいイベント」への回答を読み込み、イベントごとの参加者数と参加者一覧を集計します。

イベントについては、以下のルールで処理します。

- 応募者は全員参加
- 定員なし
- 抽選なし
- 手動確定なし
- イベント参加は練習参加回数に含めない
- 本名とLINE名を同時に出力する

練習の振り分けとイベントの集計は、同じGoogleフォーム回答CSVから別々に処理します。

```text
practice-assignment-tool/
├─ main.py
├─ README.md

├─ data/
```

### main.py

練習参加者の振り分け、イベント参加者の集計、CSVファイルの出力を行うメインプログラムです。

### data

実際に処理するGoogleフォーム回答と、手動確定情報を置きます。

個人情報を含む可能性があるため、GitHubには公開しません。

GitHub上で動作を確認するための、架空の本名とLINE名を使ったサンプルデータです。

### output

プログラムが生成した振り分け結果を保存します。

実際の参加者の本名やLINE名を含む可能性があるため、GitHubには公開しません。

## 実行環境

- Python 3
- Windows PowerShell
- 外部ライブラリなし

Pythonの標準ライブラリだけを使用しているため、追加パッケージのインストールは不要です。

## 使用方法

### 1. リポジトリを取得する

```powershell
git clone <このリポジトリのURL>
cd practice-assignment-tool
```

### 2. dataフォルダを作る

```powershell
mkdir data
```

### 3. サンプルデータをコピーする

```powershell
Copy-Item .\sample_data\responses_sample.csv .\data\responses.csv
Copy-Item .\sample_data\manual_assignments_sample.csv .\data\manual_assignments.csv
```

### 4. プログラムを実行する

```powershell
python main.py
```

実行すると、ターミナルに練習とイベントの結果が表示されます。

同時に、`output`フォルダへCSVファイルが出力されます。

```text
output/
├─ assignment_results.csv
└─ event_results.csv
```

## Googleフォーム回答CSV

Googleフォームの回答をGoogleスプレッドシートで開き、CSV形式でダウンロードして使用します。

ダウンロードしたファイルを、次の名前で保存します。

```text
data/responses.csv
```

現在のプログラムでは、以下の列名を使用します。

```text
お名前
LINE名（正確にお願いします）
参加したい練習日程(一部10時からの枠があります)
参加したいイベント
```

列名が異なる場合は、`main.py`内の設定を実際のフォームに合わせて変更する必要があります。

### 複数選択回答

1人が複数の日程やイベントを選択している場合、GoogleフォームのCSVではカンマ区切りで保存されます。

例：

```text
8/3(月)成城 17:40~, 8/10(月)学芸大学 10:00~
```

プログラムはこの文字列をカンマで分割し、それぞれの日程の応募者として登録します。

ターミナルでは、本名とLINE名を以下のように表示します。

```text

【参加者】
```

## 練習結果のCSV出力

練習の振り分け結果は、以下のファイルに保存されます。

```text
output/assignment_results.csv
```

出力する項目は以下のとおりです。

| 項目 | 内容 |
|---|---|
| 日程 | 応募した練習日程 |
| 結果 | 参加または落選 |
| 本名 | Googleフォームに入力された本名 |
| LINE名 | Googleフォームに入力されたLINE名 |
| 選出方法 | 自動選出、手動確定、または自動抽選 |
| 最終練習参加回数 | 月内で参加が確定した練習回数 |

出力例：

```csv
日程,結果,本名,LINE名,選出方法,最終練習参加回数
8/3(月)成城 17:40~,参加,田中太郎,たなか,手動確定,2
8/3(月)成城 17:40~,参加,佐藤花子,さとう,自動選出,1
8/3(月)成城 17:40~,落選,高橋美咲,みさき,自動抽選,2
```

## イベント結果のターミナル表示

イベント応募者は全員参加として、以下のように表示します。

```text

8/28 (金) BBQ
```

## イベント結果のCSV出力

イベントの集計結果は、以下のファイルに保存されます。

```text
output/event_results.csv
```

出力する項目は以下のとおりです。

| 項目 | 内容 |
|---|---|
| イベント | イベント名 |
| 参加者数 | そのイベントの参加希望者数 |
| 本名 | Googleフォームに入力された本名 |
| LINE名 | Googleフォームに入力されたLINE名 |
| 結果 | 全員参加のため常に「参加」 |

出力例：

```csv
イベント,参加者数,本名,LINE名,結果
8/28 (金) BBQ,2,田中太郎,たなか,参加
8/28 (金) BBQ,2,佐藤花子,さとう,参加
```

## 個人情報の取り扱い

実際のGoogleフォーム回答には、参加者の本名やLINE名などの個人情報が含まれます。

そのため、以下のファイルとフォルダは`.gitignore`によってGitHubの公開対象から除外しています。

```text
data/responses.csv
data/manual_assignments.csv
output/
```

GitHubには、架空の本名とLINE名で作成した`sample_data`のみを公開します。

実際の参加者データを、`sample_data`にコピーしないよう注意してください。

## 抽選結果の再現性

現在は、開発中に毎回同じ結果を確認できるよう、乱数のシードを固定しています。

```python
RANDOM_SEED = 42
```

同じ入力データを使用すると、原則として同じ抽選結果になります。

毎回異なる抽選結果にしたい場合は、乱数シードの扱いを変更する必要があります。

## 現在の制限

現在のプログラムでは、本名を応募者の識別に使用しています。

そのため、同姓同名の応募者がいる場合は正しく区別できません。

同じ本名で異なるLINE名が登録された場合は、誤った振り分けを防ぐためエラーを表示します。

将来的には、メールアドレスや回答者IDなど、一意に人物を識別できる情報を利用する方法を検討します。

また、現在の公平性判定は、日程を順番に処理し、その時点での参加回数が少ない人を優先する方式です。

すべての日程を同時に評価した最適化処理ではありません。
